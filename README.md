# Playwright Test Automation Boilerplate

Проект автоматизации UI-тестирования интернет-магазина (LiteCart) с использованием Node.js, TypeScript, Playwright и Allure Report.

---

## 1. Краткое описание проекта

Данный репозиторий представляет собой тестовый фреймворк для автоматизированной проверки сквозных (End-to-End) пользовательских сценариев веб-приложения интернет-магазина [LiteCart](https://litecart.stqa.ru/en/). Фреймворк включает в себя сценарии проверки оформления заказов авторизованным пользователем и гостем, проверки скидок, работы с корзиной, отслеживания недавно просмотренных товаров ("Recently Viewed") и обработки ошибок авторизации.

---

## 2. Используемые технологии

* **Язык программирования:** [TypeScript](https://www.typescriptlang.org/)
* **Фреймворк автоматизации:** [Playwright Test](https://playwright.dev/)
* **Отчётность:** [Allure Playwright](https://github.com/allure-framework/allure-js) & Playwright HTML Reporter
* **Управление конфигурацией:** [dotenv](https://github.com/motdotla/dotenv)
* **Среда выполнения:** [Node.js](https://nodejs.org/)


## 4. Описание реализованных тест-кейсов

1. **TC1: Заказ одного товара без скидки (`tests/ui/tc1-order-no-discount.spec.ts`)**
   * **Шаги:** Авторизация пользователя, выбор товара без скидки (`Blue Duck`), добавление требуемого количества в корзину, валидация количества и расчёта стоимости (цена за единицу × количество), последующее подтверждение заказа.
2. **TC2: Заказ товара со скидкой (`tests/ui/tc2-order-with-discount.spec.ts`)**
   * **Шаги:** Авторизация пользователя, выбор акционного товара (`Yellow Duck`), проверка отображения цены со скидкой, выбор параметров (размер), добавление в корзину, проверка итоговой суммы в корзине и успешное оформление заказа.
3. **TC3: Гостевая покупка двух товаров и проверка Recently Viewed (`tests/ui/tc3-guest-cart.spec.ts`)**
   * **Шаги:** Добавление нескольких товаров в корзину без предварительной авторизации (в режиме гостя), проверка суммы заказа и пустых данных покупателя в форме оплаты, а также валидация отображения просмотренных товаров в блоке "Recently Viewed".
4. **TC4: Невалидный логин (`tests/ui/tc4-invalid-login.spec.ts`)**
   * **Шаги:** Попытка аутентификации с некорректным паролем и проверка появления соответствующего сообщения об ошибке.

## 5. Требования для запуска

* **Node.js** версии 18.x или выше.
* **npm** (поставляется вместе с Node.js) или альтернативный пакетный менеджер (`yarn`, `pnpm`).
* **Java Runtime Environment (JRE)** или **JDK** (необходим для генерации и просмотра Allure-отчётов).

## 6. Установка зависимостей

Для установки всех необходимых npm-пакетов выполните команду в терминале:

```bash
npm install
```

---

## 7. Установка браузеров Playwright

Для установки браузерных бинарников (Chromium, Firefox, WebKit), необходимых для работы Playwright, выполните:

```bash
npm run install:browsers
```
*или напрямую:*
```bash
npx playwright install
```

---

## 8. Настройка `.env`

Перед запуском тестов необходимо создать локальный файл переменных окружения `.env` на основе шаблона `env.example` (или `.env.example`).

Скопируйте файл-шаблон:
```bash
cp env.example .env
```

Откройте созданный файл `.env` и укажите в нём ваши учётные данные и адрес тестового стенда:

```env
LOGIN=your_email@example.com
PASSWORD=your_password
BASE_URL=https://litecart.stqa.ru/en/
```

> ⚠️ **Важно:** Файл `.env` содержит персональные данные и не должен попадать в систему контроля версий (Git).

## 9. Команда запуска всех UI-тестов

Запуск всех UI-тестов в фоновом (headless) режиме:

```bash
npm test
```
*или напрямую через CLI Playwright:*
```bash
npx playwright test
```

---

## 10. Команда запуска отдельного теста

Чтобы запустить конкретный файл с тестом (например, `tc1-order-no-discount.spec.ts`):

```bash
npx playwright test tests/ui/tc1-order-no-discount.spec.ts
```

Также можно запустить конкретный тест по его названию с помощью флага `-g`:

```bash
npx playwright test -g "TC1"
```

---

## 11. Команда запуска тестов в headed mode

Для запуска тестов с графическим отображением окна браузера (headed mode):

```bash
npm run test:headed
```
*или напрямую:*
```bash
npx playwright test --project=chromium --headed
```

Дополнительные варианты отладки:
* **Режим отладки (Playwright Inspector):** `npm run test:debug`
* **Интерактивный UI Mode:** `npm run test:ui`

---

## 12. Команды для получения и открытия Allure Report

Для формирования и просмотра отчёта **Allure**:

1. Запустите генерацию и открытие отчёта командой:
   ```bash
   npm run test:report
   ```
   *(Выполняет сборку отчёта `allure generate --clean` и запускает локальный сервер `allure open`)*

2. Для просмотра стандартного **Playwright HTML Report**:
   ```bash
   npm run test:report:playwright
   ```

## 13. Краткое объяснение архитектурных решений

* **Page Object Model (POM):** Логика взаимодействия со страницами вынесена в отдельные классы (`HomePage`, `LoginPage`, `ProductPage`, `CartPage`). Это разделяет ответственность, инкапсулирует локаторы и делает тесты масштабируемыми и понятными.
* **Детализированные шаги (`test.step`):** Тесты разбиты на атомарные шаги с понятным описанием, что значительно упрощает анализ отчётов Allure/HTML и поиск причин упавших тестов.
* **Конфигурация через `.env`:** Использование модуля `dotenv` в `playwright.config.ts` избавляет от хардкода тестовых данных и позволяет безопасно менять домены и учетные данные под разные тестовые стенды.
* **Автономность тестов:** Каждый тест изолирован и проверяет отдельный бизнес-сценарий от начала до конца, не завися от порядка выполнения других тестов.
