# Playwright Test Automation Boilerplate

Проект автоматизации UI-тестирования интернет-магазина (LiteCart) с использованием Node.js, TypeScript, Playwright и Allure Report. Реализован с использованием масштабируемой архитектуры с фикстурами, Page Object Model и best practices.

---

## 1. Краткое описание проекта

Данный репозиторий представляет собой тестовый фреймворк для автоматизированной проверки сквозных (End-to-End) пользовательских сценариев веб-приложения интернет-магазина [LiteCart](https://litecart.stqa.ru/en/). Фреймворк включает в себя сценарии проверки оформления заказов авторизованным пользователем и гостем, проверки скидок, работы с корзиной, отслеживания недавно просмотренных товаров ("Recently Viewed") и обработки ошибок авторизации.

## 2. Архитектура проекта

### Структура директорий
```text
playwright-boilerplate/
├── pages/                          # Page Object Model (POM) классы страниц
│   ├── BasePage.ts                 # Базовый класс для всех страниц
│   ├── CartPage.ts                 # Страница корзины и оформления заказа
│   ├── HomePage.ts                 # Главная страница магазина
│   ├── LoginPage.ts                # Страница входа в систему
│   └── ProductPage.ts              # Страница карточки товара
├── tests/                          # Директория с автотестами
│   └── ui/                         # UI E2E тесты
│       ├── tc1-order-no-discount.spec.ts  # TC1: Заказ товара без скидки
│       ├── tc2-order-with-discount.spec.ts # TC2: Заказ товара со скидкой
│       ├── tc3-guest-cart.spec.ts          # TC3: Гостевая покупка и Recently Viewed
│       └── tc4-invalid-login.spec.ts       # TC4: Ошибка невалидного логина
├── fixtures/                       # Playwright фикстуры для переиспользования
│   ├── authenticated.ts            # Фикстуры для авторизованных пользователей
│   ├── guest.ts                    # Фикстуры для гостевых пользователей
│   └── page-objects.ts             # Фикстуры со всеми page objects
├── utils/                          # Вспомогательные утилиты и хелперы
│   └── price.ts                    # Утилиты для работы с ценами
├── data/                           # Тестовые данные
│   └── products.ts                 # Данные о товарах
├── types/                          # TypeScript типы и интерфейсы
│   └── index.ts                    # Общие типы для тестов
├── config/                         # Конфигурация приложения
│   └── env.ts                      # Управление переменными окружения
├── env.example                     # Шаблон файла конфигурации переменных окружения
├── playwright.config.ts            # Конфигурационный файл Playwright
├── package.json                    # Зависимости и npm-скрипты
└── tsconfig.json                   # Настройки компилятора TypeScript
```

### Особенности архитектуры

1. **Фикстуры Playwright** - переиспользуемая логика для разных типов тестов:
   - `authenticated.ts` - для тестов с авторизованными пользователями
   - `guest.ts` - для тестов в режиме гостя
   - `page-objects.ts` - предоставляет все page objects сразу

2. **Page Object Model** - чистое разделение логики страниц и тестов:
   - `BasePage.ts` - базовый класс с общими методами
   - Каждая страница наследует от BasePage и содержит только свои селекторы и методы

3. **TypeScript path aliases** - короткие импорты через `@pages/*`, `@fixtures/*`, `@utils/*`, `@data/*`, `@models/*` и `@config/*`.

4. **Централизованная конфигурация** - управление переменными окружения через `config/env.ts`

5. **Тестовые данные** - разделение данных от логики тестов в `data/products.ts`

## 4. Описание реализованных тест-кейсов

1. **TC1: Заказ одного товара без скидки (`tests/ui/tc1-order-no-discount.spec.ts`)**
   * **Шаги:** Авторизация пользователя, выбор товара без скидки (`Blue Duck`), добавление требуемого количества в корзину, валидация количества и расчёта стоимости (цена за единицу × количество), последующее подтверждение заказа.

2. **TC2: Заказ товара со скидкой (`tests/ui/tc2-order-with-discount.spec.ts`)**
   * **Шаги:** Авторизация пользователя, выбор акционного товара (`Yellow Duck`), проверка отображения цены со скидкой, выбор параметров (размер), добавление в корзину, проверка итоговой суммы в корзине и успешное оформление заказа.

3. **TC3: Гостевая покупка двух товаров и проверка Recently Viewed (`tests/ui/tc3-guest-cart.spec.ts`)**
   * **Шаги:** Добавление нескольких товаров в корзину без предварительной авторизации (в режиме гостя), проверка суммы заказа и пустых данных покупателя в форме оплаты, а также валидация отображения просмотренных товаров в блоке "Recently Viewed".

4. **TC4: Невалидный логин (`tests/ui/tc4-invalid-login.spec.ts`)**
   * **Шаги:** Попытка аутентификации с некорректным паролем и проверка появления соответствующего сообщения об ошибке.

## 5. Требования для запуска

* **Node.js** версии 18.x или выше.
* **npm** (поставляется вместе с Node.js) или альтернативный пакетный менеджер (`yarn`, `pnpm`).
* **Java Runtime Environment (JRE)** или **JDK** (необходим для генерации и просмотра Allure-отчётов).

## 6. Установка зависимостей

Для установки всех необходимых npm-пакетов выполните команду в терминале:

```bash
npm install
```

---

## 7. Установка браузеров Playwright

Для установки браузерных бинарников (Chromium, Firefox, WebKit), необходимых для работы Playwright, выполните:

```bash
npm run install:browsers
```
*или напрямую:*
```bash
npx playwright install
```

---

## 8. Настройка `.env`

Перед запуском тестов необходимо создать локальный файл переменных окружения `.env` на основе шаблона `env.example` (или `.env.example`).

Скопируйте файл-шаблон:
```bash
cp env.example .env
```

Затем заполните переменные:
- `LOGIN` - email для авторизации
- `PASSWORD` - пароль для авторизации
- `BASE_URL` - базовый URL приложения (по умолчанию: https://litecart.stqa.ru/en/)

## 9. Запуск тестов

### Доступные npm-скрипты:
- `npm test` - запуск всех тестов в headless режиме
- `npm run test:headed` - запуск тестов в headed режиме (видно браузер)
- `npm run test:debug` - запуск тестов в режиме отладки
- `npm run test:ui` - запуск тестов с Playwright UI
- `npm run test:report` - генерация и открытие Allure отчёта
- `npm run test:report:playwright` - показ встроенного Playwright отчёта
- `npm run install:browsers` - установка браузеров Playwright
- `npm run typecheck` - проверка TypeScript типов
- `npm run typecheck:fix` - автоисправление TypeScript ошибок

### Примеры запуска:
```bash
# Запуск всех тестов
npm test

# Запуск конкретного тест-файла
npx playwright test tests/ui/tc1-order-no-discount.spec.ts

# Запуск тестов с отчётом Allure
npm run test:report
```

## 10. CI/CD интеграция

В репозитории настроен GitHub Actions workflow (`.github/workflows/playwright.yml`) для автоматического запуска тестов при push и pull request в ветки main/master.

Workflow включает:
- Checkout кода
- Setup Node.js
- Установка зависимостей
- Установка браузеров Playwright
- Запуск тестов
- Сохранение артефакта с Playwright отчётом

## 11. Лучшие практики, реализованные в проекте

1. **Изоляция тестов** - каждый тест запускается в чистом контексте браузера
2. **Переиспользуемая логика** - фикстуры и page objects уменьшают дублирование кода
3. **Чистый код** - разделение ответственностей между слоями (тесты, страницы, утилиты, данные)
4. **TypeScript строгий режим** - использование strict: true для раннего обнаружения ошибок
5. **Обработка ошибок** - явные ожидания и проверки состояния
6. **Скриншоты и видео** - автоматическое capture при падении тестов
7. **Игнорирование HTTPS ошибок** - для работы с self-signed сертификатами в тестовых окружениях
8. **Параллелизм control** - отключен параллелизм для стабильности, но легко настраивается
9. **Повторные попытки** - автоматическое повторение падающих тестов в CI
10. **Трассировка** - capture трассировки при первой неудачной попытке для отладки

## 12. Расширение проекта

### Добавление нового теста:
1. Создайте новый файл в `tests/ui/` с префиксом `tc` и описанием
2. Выберите подходящую фикстуру (`authenticated`, `guest`, `page-objects`)
3. Используйте page objects для взаимодействия со страницами
4. Разместите тестовые данные в `data/products.ts` если нужно
5. Добавьте новые типы в `types/index.ts` если необходимо

### Добавление новой страницы:
1. Создайте файл в `pages/` наследуя от `BasePage.ts`
2. Определите селекторы в конструкторе
3. Добавьте методы для взаимодействия со страницей
4. Экспортируйте класс

### Добавление новых утилит:
1. Создайте файл в `utils/` с конкретной функциональностью
2. Экспортируйте функции
3. Импортируйте там, где нужно
